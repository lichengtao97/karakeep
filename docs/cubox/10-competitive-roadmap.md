# Karakeep x Cubox 竞品路线图

## 背景

这份路线图以 Cubox 作为参考产品，用来明确 Karakeep 接下来的产品方向。核心转变是：

> 将 Karakeep 从“书签归档工具”推进为“自托管 AI 阅读库”。

Cubox 当前的优势不只是保存链接，而是形成了一条完整的产品闭环：

1. 从多个入口收集内容。
2. 在干净的阅读环境中阅读。
3. 高亮、标注并保存重要片段。
4. 搜索、回顾并重新发现阅读资产。
5. 使用 AI 和 Agent 理解、总结、整理并操作整个阅读库。

Karakeep 已经具备很强的技术底座：自托管、全文归档、RSS 自动收集、移动端、浏览器扩展、API、MCP、规则引擎、AI 自动标签、自动摘要、OCR、全文搜索和语义搜索。下面的路线图会优先围绕阅读、标注、AI 和 Agent 工作流来增强产品连贯性。

## 产品定位

Karakeep 不应该被定位成 Cubox 的直接复刻。

推荐定位：

> 一个自托管、开放、可编程的 AI 阅读库，面向重视数据所有权、隐私、自动化和长期知识访问的用户。

相对 Cubox 的差异化：

- 自托管优先。
- 开放 API 和 MCP 优先。
- 适合本地模型和私有化部署。
- 适合自动化和规则引擎场景。
- 适合长期归档和多媒体保存。
- 天然面向 AI Agent 读取和操作。

## 阶段 1：阅读闭环 MVP

目标：让 Karakeep 从“已保存项目库”变成日常使用的稍后阅读产品。

### 范围

- [ ] 将未读页升级为主要阅读收件箱。
- [ ] 增加清晰分区：未读、最近保存、继续阅读、最近读过。
- [ ] 强化全局阅读状态：未读、已读、归档、收藏、阅读进度。
- [ ] 在列表和卡片中展示阅读进度。
- [ ] 在卡片上增加快捷操作：标记已读、归档、收藏、加入列表、添加标签。
- [ ] 优化从书签卡片进入阅读器的路径。
- [ ] 增加“继续阅读”模块。
- [ ] 确保移动端支持未读队列和继续阅读。

### 验收标准

- 用户打开 Karakeep 后能立即知道下一篇该读什么。
- 用户可以开始阅读、暂停、恢复和完成阅读，而不需要手动管理书签状态。
- 未读页具备替代 Pocket / Cubox 式稍后阅读工作流的基础体验。

### 优先级

最高。

## 阶段 2：高亮与笔记体系

目标：让高亮成为一等知识对象，而不只是文章内部的附属元数据。

### 范围

- [ ] 改进阅读器中的文本高亮体验。
- [ ] 支持高亮颜色。
- [ ] 支持给高亮添加笔记。
- [ ] 保存稳定的原文定位信息，确保高亮可以跳回原文位置。
- [ ] 在阅读器中增加当前文章的高亮侧栏或面板。
- [ ] 升级全局高亮页，支持按文章、标签、列表、颜色、日期和关键词筛选。
- [ ] 将高亮纳入全文搜索。
- [ ] 将高亮纳入语义搜索。
- [ ] 为高亮增加复制和导出操作。
- [ ] 增加随机高亮回顾。
- [ ] 增加每日或每周高亮回顾入口。

### 验收标准

- 用户无需逐篇打开文章，也能回顾所有重要片段。
- 高亮内容可搜索、可复用。
- 高亮能成为后续 AI 功能的重要上下文。

### 优先级

高。

## 阶段 3：单篇文章 AI 阅读增强

目标：让每个已保存项目更容易判断、理解和复用。

### 范围

- [ ] 为单个书签增加结构化 AI 解读。
- [ ] 生成一句话结论。
- [ ] 生成关键要点。
- [ ] 生成文章提出的重要问题。
- [ ] 生成“值得精读 / 可以略读 / 建议归档”的阅读建议。
- [ ] 增加文章级 AI 问答。
- [ ] 增加阅读器内选中文本后的 AI 问答。
- [ ] 允许将 AI 回答保存为书签笔记或高亮笔记。
- [ ] 根据 AI 输出推荐标签和列表。
- [ ] 支持用户自定义单篇文章解读提示词。

### 建议输出结构

- 一句话结论。
- 摘要。
- 核心论点。
- 有价值的引用或相关片段。
- 推荐标签。
- 推荐列表。
- 阅读建议。
- 后续追问。

### 验收标准

- 用户能在一分钟内判断一篇保存内容是否值得阅读。
- AI 输出不只是展示结果，还能写回用户自己的阅读库。
- AI 功能对新保存内容和历史归档内容都有效。

### 优先级

高。

## 阶段 4：全库 AI 搜索与问答

目标：让用户可以直接向自己的收藏库提问。

### 范围

- [ ] 在 UI 中统一普通搜索、全文搜索和语义搜索入口。
- [ ] 增加自然语言全库问答界面。
- [ ] 支持限定提问范围：未读 / 已读、归档状态、标签、列表、来源、内容类型、时间范围。
- [ ] 回答必须返回引用来源：书签、原始 URL、标题、命中片段，如有相关高亮也一并返回。
- [ ] 允许用户将问答结果保存为笔记。
- [ ] 允许用户将问答结果转成阅读清单。
- [ ] 增加常用问题模板：“总结最近保存内容”、“查找关于 X 的未读内容”、“对比关于 X 的几篇文章”、“我关于 X 高亮过什么”。
- [ ] 增加带确认的结果级操作：归档、标记已读、添加标签、加入列表。

### 验收标准

- 回答基于已保存内容，并包含可追溯引用。
- 用户可以从“提问”自然进入“整理”，不需要离开当前流程。
- 现有语义搜索能力变成用户可见的产品功能，而不只是 API 能力。

### 优先级

中高。

## 阶段 5：AI 自动整理与报告

目标：让阅读库主动产生价值，减少用户的手动清理负担。

### 范围

- [ ] 生成每周阅读摘要。
- [ ] 生成每周未读清理建议。
- [ ] 生成“本周最值得读的保存内容”报告。
- [ ] 跟踪最近保存内容或指定标签中的主题变化。
- [ ] 检测重复或近似重复书签。
- [ ] 推荐低价值未读内容归档。
- [ ] 为未分类书签推荐列表归属。
- [ ] 推荐标签规范化和标签合并。
- [ ] 允许规则引擎在新保存内容后触发 AI 工作流。
- [ ] 允许用户配置周期性 AI 问题。

### 验收标准

- 用户即使不主动搜索，也能定期获得有用输出。
- 未读积压更容易被管理。
- 产品通过周期性回顾和报告形成留存闭环。

### 优先级

中。

## 阶段 6：浏览器扩展阅读场景

目标：在用户遇到内容的当下，支持收集、标注和 AI 阅读。

### 范围

- [ ] 显示当前页面是否已经保存。
- [ ] 保存当前页面时支持选择列表、标签、笔记和归档偏好。
- [ ] 支持将选中文本保存为文本书签。
- [ ] 支持直接在原始网页上高亮文本。
- [ ] 将网页高亮同步回 Karakeep，并按 URL 聚合。
- [ ] 支持从网页中裁剪图片片段。
- [ ] 在扩展中运行 AI 页面解读。
- [ ] 在扩展中运行 AI 选中文本问答。
- [ ] 将客户端全文归档作为可见选项。

### 验收标准

- 浏览器扩展不再只是保存按钮，而是阅读伴侣。
- 用户可以在原始网页上直接捕捉自己的思考。
- 网页标注和阅读器标注进入同一套高亮体系。

### 优先级

中。

## 阶段 7：开放集成与 Agent 工作流

目标：让 Karakeep 成为人和 AI Agent 都可以使用的可编程个人阅读记忆库。

### 范围

- [ ] 扩展 MCP tools，支持读取书签正文。
- [ ] 扩展 MCP tools，支持读取摘要。
- [ ] 扩展 MCP tools，支持读取高亮。
- [ ] 扩展 MCP tools，支持更新已读、归档、收藏状态。
- [ ] 扩展 MCP tools，支持安全的批量操作。
- [ ] 增加 MCP resources：书签、高亮、列表、标签、阅读正文。
- [ ] 为破坏性操作或大范围 Agent 操作增加确认层。
- [ ] 增加 CLI 搜索、阅读、导出和批量整理能力。
- [ ] 增加 Obsidian 导出或同步。
- [ ] 增加 Notion 导出或同步。
- [ ] 增加 Readwise 导出或同步。
- [ ] 增加 Markdown 导出包。
- [ ] 增加 webhook 事件：高亮创建、摘要完成、阅读完成、AI 报告生成。
- [ ] 提供官方提示词或 skill，帮助 AI 助手安全使用 Karakeep。

### 验收标准

- Agent 可以检索并引用已保存的阅读内容。
- Agent 只能通过明确、安全的动作整理阅读库。
- Karakeep 成为个人知识工作流的强后端。

### 优先级

中。

## 推荐开发顺序

1. 先做阶段 1 和阶段 2：补齐阅读闭环和高亮体系。
2. 接着做阶段 3：单篇文章 AI 阅读，因为它最容易被用户感知，也能复用现有摘要能力。
3. 再做阶段 4：全库问答，把现有搜索和语义搜索包装成用户可用的工作流。
4. 然后做阶段 5：周期性报告和自动清理。
5. 阶段 6 和阶段 7 在资源允许时并行推进：浏览器阅读场景和 Agent 场景。

## MVP 建议

第一个产品里程碑建议包含：

- 未读首页。
- 阅读进度。
- 高亮与笔记。
- 单篇文章 AI 解读。
- 全库语义搜索入口。

这组功能足够小，可以分步交付；同时也足够关键，能把产品从“书签管理”推进到“AI 辅助阅读”。
