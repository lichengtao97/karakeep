# AI Lens 产品与业务设计文档

## 1. 文档目的

本文档用于指导 AI Lens 的 UI/UX 设计和早期产品原型设计。

它重点回答：

- 产品服务谁。
- 用户为什么需要它。
- 业务闭环如何成立。
- H5 第一阶段应该有哪些页面。
- 每个核心页面承载什么信息和操作。
- 设计上应该突出什么、弱化什么。
- MVP 阶段哪些能力必须有，哪些能力后置。

本文档不展开底层工程实现，也不作为数据库或接口设计文档。

## 2. 产品定义

### 2.1 产品名称

暂定名称：AI Lens

### 2.2 一句话定位

AI Lens 是面向 AI 产品人、创业者和团队决策者的个性化 AI 资讯阅读库。

### 2.3 产品解释

AI Lens 自动收集 AI 行业的重要资讯，通过 AI 进行筛选、摘要、打标和去重，再根据用户的关注方向、收藏内容和阅读反馈，生成个性化资讯流、每日简报和每周总结。

用户不需要每天主动刷信息源，也不需要手动整理大量链接。产品帮助用户完成从“发现信息”到“理解信息”再到“沉淀为个人阅读资产”的完整闭环。

## 3. 产品边界

### 3.1 我们要做什么

- AI 领域高价值资讯发现。
- 个性化 AI 资讯收件箱。
- 干净、流畅的 H5 阅读体验。
- AI 摘要、标签、推荐理由和重要性判断。
- 收藏、已读、不感兴趣等反馈闭环。
- 每日 AI 简报和每周个人总结。
- 长期阅读库、搜索、收藏和回顾。

### 3.2 我们暂时不做什么

- 不做泛资讯平台。
- 不做完整社交社区。
- 不做通用笔记软件。
- 不在 MVP 阶段做复杂团队协作。
- 不在 MVP 阶段做完整 Cubox 复刻。
- 不优先做论文管理器或学术研究工具。

### 3.3 和 Cubox 的关系

Cubox 的核心是“收藏、阅读、标注、回顾、AI 理解阅读库”。

AI Lens 借鉴这个阅读资产闭环，但产品重心不同：

| 对比项 | Cubox | AI Lens |
| --- | --- | --- |
| 核心入口 | 用户主动收藏 | 系统主动推荐 + 用户收藏 |
| 内容范围 | 泛内容阅读库 | AI 领域资讯和阅读资产 |
| 核心价值 | 稍后读与知识管理 | 高价值 AI 资讯发现和决策辅助 |
| AI 作用 | 理解和整理已有内容 | 筛选新资讯 + 理解内容 + 个性化推荐 |
| 首页心智 | 未读/收藏库 | 个性化 AI 资讯收件箱 |

## 4. 目标用户

### 4.1 核心用户

#### AI 产品经理

关心：

- 新模型能力。
- 新产品形态。
- 竞品动态。
- 用户场景。
- 商业化机会。

痛点：

- 信息源分散。
- 很多资讯标题党，难判断价值。
- 没时间逐篇阅读。
- 看过的信息难以回顾。

#### AI 创业者

关心：

- 新技术窗口。
- 新平台政策。
- 新产品机会。
- 竞争格局。
- 融资和市场变化。

痛点：

- 需要快速判断趋势是否重要。
- 需要发现可行动的信息。
- 需要把资讯转化为产品判断。

#### 团队负责人 / 决策者

关心：

- AI 行业重大变化。
- 对业务的潜在影响。
- 团队应该关注什么。
- 哪些方向值得投入。

痛点：

- 不想陷入信息细节。
- 希望获得高信噪比总结。
- 希望定期看到结构化报告。

### 4.2 非核心用户

- 只想收藏网页的普通用户。
- 只关注娱乐资讯的用户。
- 需要深度论文引用管理的研究者。
- 需要企业知识库权限体系的组织客户。

## 5. 核心业务目标

### 5.1 用户目标

- 更快知道 AI 行业发生了什么。
- 更快判断一条资讯是否值得读。
- 持续跟踪自己关注的模型、公司、产品和技术方向。
- 把有价值的资讯沉淀为个人阅读资产。
- 定期获得个人化总结，而不是通用新闻摘要。

### 5.2 产品目标

- 建立高质量 AI 资讯供给能力。
- 建立用户偏好和行为反馈闭环。
- 建立每日和每周触达机制。
- 让用户形成持续打开和收藏的习惯。
- 从 H5 验证核心体验，再扩展插件、iOS、Mac 等多端。

### 5.3 商业目标

MVP 阶段优先验证留存和推荐价值，不急于复杂商业化。

后续可探索：

- Pro 订阅：更多资讯源、更深总结、更高频推送。
- 主题追踪：指定公司、模型、竞品或技术方向。
- 团队版：共享资讯库、团队周报、成员关注点。
- 专业报告：按行业或岗位生成趋势报告。

## 6. 产品核心闭环

```text
外部资讯源
  -> 自动采集
  -> AI 清洗、去重、摘要、打标、评分
  -> 个性化资讯收件箱
  -> 用户阅读、收藏、忽略、分享
  -> 用户兴趣画像更新
  -> 每日简报 / 每周总结 / 后续推荐
```

这个闭环中，UI 需要重点表现三件事：

- 这条资讯讲了什么。
- 为什么推荐给我。
- 我可以如何反馈，让后续推荐更准。

## 7. MVP 信息架构

### 7.1 一级导航

H5 第一阶段推荐使用以下一级导航：

| 导航 | 说明 | 优先级 |
| --- | --- | --- |
| 今日 | 个性化 AI 资讯收件箱，默认首页 | P0 |
| 简报 | 每日简报、每周总结、历史报告 | P0 |
| 阅读库 | 收藏、稍后读、已读、归档内容 | P0 |
| 搜索 | 搜索资讯和个人阅读库 | P1 |
| 偏好 | 关注方向、推送设置、账号设置 | P0 |

移动端底部导航建议：

- 今日
- 简报
- 阅读库
- 搜索
- 我的

### 7.2 内容对象

UI 设计需要理解以下核心对象：

| 对象 | 含义 |
| --- | --- |
| 资讯 Article | 系统采集并筛选后的单条内容 |
| 事件 Cluster | 多条资讯合并后的同主题事件 |
| 推荐 Recommendation | 系统给某个用户展示的资讯或事件 |
| 收藏 Saved Item | 用户主动保存的内容 |
| 阅读状态 Read State | 未读、已读、稍后读、归档 |
| 用户偏好 Preference | 用户显式选择的关注方向 |
| 用户反馈 Feedback | 收藏、忽略、已读、分享、点击等行为 |
| 简报 Briefing | 每日或每周生成的总结 |

## 8. 核心页面设计说明

### 8.1 新用户引导页

目标：在 3 分钟内完成冷启动偏好设置。

页面任务：

- 解释产品价值。
- 让用户选择关注方向。
- 让用户选择推送频率。
- 生成第一版个性化资讯流。

推荐流程：

1. 欢迎页：一句话说明产品价值。
2. 选择关注角色：产品、创业、技术、投资、运营。
3. 选择关注主题：模型、Agent、AI 编程、AI 搜索、多模态、开源、商业化、融资、出海等。
4. 选择关注公司：OpenAI、Anthropic、Google、Meta、Microsoft、Apple、NVIDIA、Perplexity、字节、阿里、腾讯等。
5. 设置推送：每日简报、每周总结、重大事件提醒。
6. 进入今日首页。

设计重点：

- 不要做复杂问卷。
- 每一步选项不宜过多。
- 支持跳过，但应保留默认推荐。
- 明确告诉用户“可以稍后修改偏好”。

### 8.2 今日首页：个性化 AI 资讯收件箱

目标：用户打开产品后快速知道今天最值得看的 AI 资讯。

页面结构建议：

1. 顶部日期和简短问候。
2. 今日重点摘要。
3. 重要资讯卡片列表。
4. 主题分组。
5. 继续阅读或最近收藏。

首屏必须展示：

- 今天最重要的 3 到 5 条资讯。
- 每条资讯的标题。
- AI 摘要。
- 推荐理由。
- 来源。
- 发布时间。
- 主题标签。
- 收藏、已读、不感兴趣操作。

资讯卡片字段：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| 标题 | 是 | 保留原始标题或 AI 优化后的清晰标题 |
| 摘要 | 是 | 2 到 4 行，说明核心信息 |
| 推荐理由 | 是 | 解释和用户偏好的关系 |
| 来源 | 是 | 来源平台或原始站点 |
| 时间 | 是 | 发布时间或采集时间 |
| 标签 | 是 | 公司、模型、主题、内容类型 |
| 重要性 | 建议 | 可用高/中/低或视觉权重体现 |
| 相关事件 | 可选 | 有同主题内容时展示 |

核心操作：

- 打开阅读。
- 收藏。
- 稍后读。
- 标记已读。
- 不感兴趣。
- 分享。

设计重点：

- 首页不是新闻瀑布流，而是高信噪比收件箱。
- 卡片应适合快速扫描，不要过度装饰。
- 推荐理由必须可见，但不应喧宾夺主。
- “不感兴趣”是重要反馈入口，不应隐藏太深。

### 8.3 资讯详情 / 阅读页

目标：让用户在干净环境中理解内容，并沉淀为阅读资产。

页面结构建议：

1. 标题、来源、时间、原文链接。
2. AI 阅读摘要。
3. 关键要点。
4. 对产品/业务的影响判断。
5. 正文阅读区。
6. 标签、相关资讯、用户笔记。
7. 底部或浮动操作栏。

AI 阅读摘要建议包含：

- 一句话结论。
- 关键要点。
- 可能影响。
- 适合谁关注。
- 建议操作：精读、略读、收藏观察、忽略。

核心操作：

- 收藏。
- 高亮。
- 添加笔记。
- 加入列表。
- 分享。
- 打开原文。
- 标记已读。

设计重点：

- 阅读页要安静、少干扰。
- AI 摘要应帮助用户决定是否继续读。
- 正文区域要保持良好排版和移动端可读性。
- 操作栏要稳定，不要遮挡正文。

### 8.4 每日简报页

目标：把当天 AI 行业重点压缩成可快速阅读的结构化页面。

页面内容：

- 今日一句话总结。
- 今日最重要事件。
- 按主题分组的资讯。
- 用户关注方向更新。
- 建议精读内容。
- 已收藏但未读提醒。

主题分组示例：

- 模型发布。
- AI Agent。
- AI 编程。
- 多模态。
- 开源项目。
- 投融资。
- 大厂动态。
- 产品案例。

设计重点：

- 简报不是资讯列表的重复。
- 要更像“今日 AI 行业判断”。
- 适合用户在 3 到 5 分钟内读完。

### 8.5 每周总结页

目标：帮助用户从一周资讯中看到趋势和个人关注变化。

页面内容：

- 本周核心变化。
- 本周高频主题。
- 用户最关注的方向。
- 用户收藏内容总结。
- 值得继续跟踪的公司/模型/产品。
- 下周关注建议。

设计重点：

- 更强调趋势，不强调每条新闻。
- 应有清晰的信息层级。
- 可以使用轻量图表，但不要复杂数据看板化。

### 8.6 阅读库页

目标：承载用户长期保存的 AI 阅读资产。

页面分区：

- 收藏。
- 稍后读。
- 已读。
- 高亮。
- 标签。
- 列表。

列表项应展示：

- 标题。
- 摘要。
- 标签。
- 阅读状态。
- 收藏时间。
- 来源。

核心操作：

- 搜索。
- 筛选。
- 批量归档。
- 加标签。
- 加入列表。
- 打开阅读。

设计重点：

- 阅读库不是首页主角，但必须可靠。
- 用户要能快速找回过去保存的重要内容。
- 标签和列表不要在 MVP 阶段设计得过重。

### 8.7 搜索页

目标：搜索系统资讯和个人阅读资产。

搜索范围：

- 标题。
- 摘要。
- 正文。
- 标签。
- 收藏内容。
- 高亮和笔记。

MVP 搜索结果结构：

- 最相关资讯。
- 我的收藏。
- 标签建议。
- 相关主题。

后续增强：

- 自然语言提问。
- 引用来源回答。
- 限定范围问答。

设计重点：

- 搜索结果要解释匹配原因。
- 收藏内容应和普通资讯区分。
- 不要一开始就把搜索设计成复杂聊天界面。

### 8.8 偏好设置页

目标：让用户控制推荐方向和推送方式。

页面内容：

- 我的角色。
- 关注主题。
- 关注公司。
- 不感兴趣主题。
- 推送频率。
- 邮件设置。
- 推荐反馈历史。

设计重点：

- 偏好设置应该像“调推荐”，不是普通账号设置。
- 用户需要看到当前偏好如何影响推荐。
- 支持快速增加或移除关注方向。

### 8.9 邮件简报

目标：把用户拉回产品，并提供独立可读价值。

邮件结构：

- 今日标题。
- 一句话总览。
- 3 到 5 条重点资讯。
- 每条资讯的摘要和推荐理由。
- 进入 H5 阅读按钮。
- 管理推送偏好入口。

设计重点：

- 邮件不应只是链接集合。
- 需要在邮件内直接提供价值。
- CTA 应指向 H5 今日页或具体阅读页。

## 9. 核心用户流程

### 9.1 新用户冷启动流程

```text
注册/登录
  -> 选择角色
  -> 选择关注主题
  -> 选择关注公司
  -> 选择推送设置
  -> 生成今日资讯收件箱
  -> 阅读/收藏/忽略
  -> 推荐模型开始校准
```

### 9.2 每日使用流程

```text
收到邮件或打开 H5
  -> 查看今日重点
  -> 快速扫读资讯卡片
  -> 打开重要内容
  -> 收藏或标记已读
  -> 忽略不相关内容
  -> 系统更新偏好
```

### 9.3 深度阅读流程

```text
打开资讯详情
  -> 先读 AI 摘要
  -> 判断是否精读
  -> 阅读正文
  -> 高亮或添加笔记
  -> 收藏到阅读库
  -> 后续在周报或搜索中回顾
```

### 9.4 周期回顾流程

```text
打开每周总结
  -> 查看本周趋势
  -> 查看个人关注方向变化
  -> 回顾收藏内容
  -> 选择下周继续关注的主题
  -> 调整偏好
```

## 10. 关键状态设计

### 10.1 资讯状态

- 新推荐。
- 已读。
- 稍后读。
- 已收藏。
- 已忽略。
- 已归档。

### 10.2 推荐状态

- 高相关。
- 可能相关。
- 探索推荐。
- 因关注主题推荐。
- 因收藏行为推荐。
- 因行业重要性推荐。

### 10.3 采集状态

普通用户侧不需要暴露复杂采集状态。

可在必要时展示：

- 来源。
- 发布时间。
- 最近更新。
- 原文不可访问。
- 内容提取不完整。

### 10.4 空状态

需要重点设计：

- 新用户无推荐。
- 用户无收藏。
- 搜索无结果。
- 简报尚未生成。
- 邮件未开启。
- 偏好过少导致推荐不足。

空状态不应只是提示错误，而应提供下一步操作。

## 11. 设计原则

### 11.1 高信噪比

界面应传递“精选、可靠、专业”，不要像泛资讯流一样无限滚动和强刺激。

### 11.2 工作台气质

目标用户是产品人、创业者和决策者。视觉上应偏克制、清晰、信息密度适中，避免过度营销感。

### 11.3 移动端优先

第一阶段是 H5，应确保手机上：

- 卡片可快速扫描。
- 正文可长时间阅读。
- 收藏、已读、不感兴趣操作足够顺手。
- 从邮件跳转到 H5 的体验流畅。

### 11.4 推荐可解释

推荐理由是产品信任的核心，不应被隐藏。

推荐理由示例：

- 因为你关注 AI Agent 和企业自动化。
- 因为你收藏过 Claude Code 相关内容。
- 因为这是你关注公司 OpenAI 的官方更新。
- 因为这条内容在多个技术社区被高频讨论。

### 11.5 AI 是辅助，不是表演

AI 输出应服务阅读和决策，不要堆砌“智能感”组件。摘要、推荐理由、趋势判断比聊天入口更重要。

## 12. UI 设计交付建议

第一轮 UI 原型建议交付以下页面：

1. 新用户偏好引导。
2. 今日首页。
3. 资讯卡片组件。
4. 资讯详情/阅读页。
5. 每日简报页。
6. 每周总结页。
7. 阅读库页。
8. 偏好设置页。
9. 邮件简报模板。

需要覆盖：

## 14. 关键指标

### 激活指标

- 新用户完成偏好设置比例。
- 首次进入后阅读第一条资讯比例。
- 首日收藏或忽略行为比例。

### 留存指标

- 次日打开率。
- 每周打开率。
- 邮件点击率。
- 每周总结打开率。

### 推荐质量指标

- 收藏率。
- 不感兴趣率。
- 资讯打开率。
- 单条资讯阅读完成率。
- 用户主动调整偏好的次数。

### 阅读资产指标

- 人均收藏数。
- 人均高亮数。
- 搜索使用次数。
- 周报中回访历史收藏的比例。

## 15. 需要继续确认的问题

进入 UI 设计前，建议确认以下问题：

1. 产品正式名称是否确定为 AI Lens。
2. 第一版视觉气质更偏“专业工作台”还是“媒体资讯产品”。
3. 首页资讯卡片是偏紧凑列表，还是偏大卡片阅读流。
4. 邮件简报是否必须进入第一版 UI 范围。
5. 是否需要在第一版设计中体现付费订阅入口。
6. 是否需要为团队版预留导航或入口。
